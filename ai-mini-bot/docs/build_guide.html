01

How it works

The split that makes the whole thing possible.

The ESP32 can't run a large language model — nowhere near. So it doesn't try. The board handles the physical parts: it draws the animated face on the OLED and takes a photo when asked. Everything intelligent — hearing you, thinking, choosing words, remembering — runs in a Python program on your Mac. The two talk over your Wi-Fi.

The body

XIAO ESP32S3

  • Draws the OLED face (15 expressions)
  • Onboard camera → one photo on request
  • Two tiny web endpoints: set the face, grab a frame
  • Sits on your desk, powered by USB
emotion ← ⇄ → photo Wi-Fi
The brain

Your Mac (Python)

  • Hears you, thinks, and replies as text
  • Speaks the reply in a cloned voice
  • Remembers every conversation, locally
  • Can search, take notes, open apps, check the system
Why turn-based, not a live callThe robot listens, then speaks, with its microphone muted while it talks. This is deliberate: on laptop speakers, a fully live voice hears its own voice and cuts itself off mid-sentence. Waiting its turn is what keeps it from tripping over itself. More on this in the gotchas.

Wiring the face

Four wires. The camera is already onboard — nothing to connect.

The OLED talks to the board over I²C, which needs just two data lines plus power. On the XIAO, the default I²C pins are D4 and D5.

Soldering the headerMost OLEDs ship with a loose 4-pin header. Push the pins through from the back so they poke out the labelled front, tape it flush, solder the two outer pins first, check it sits straight, then do the middle two. Insulate each joint and power-test before mounting anything into the body.
04

Flashing the body

Load the firmware onto the ESP32 with the Arduino IDE.

Board setup

Install the ESP32 boards package in the Arduino IDE, then set these under Tools — they matter, especially the PSRAM one:

BoardXIAO_ESP32S3
PSRAMOPI PSRAM  — required, or the camera fails to start
USB CDC On BootEnabled  — so you get serial output

Install two libraries from the Library Manager: Adafruit GFX and Adafruit SSD1306.

Set your Wi-Fi, then upload

Open bot_face_phase3a.ino, put in your network name and password near the top, and upload.

const char* ssid     = "your-wifi-name";
const char* password = "your-wifi-password";

Open the Serial Monitor. When it connects, it prints the robot's address — write it down, the brain needs it:

Connecting to WiFi....
Bot IP: 192.168.1.XX
Camera: ready

Check it before moving on

Open http://<that-ip>/ in a browser. You get a little control page — tap the face buttons and watch the OLED switch expressions, and hit look to confirm the camera returns a photo. If both work, the body is done.

05

Setting up the brain

Three Python files on your Mac do the thinking, remembering, and acting.

bot_brain_realtime.pyThe main loop — hears you, thinks, speaks, drives the face
memory.pyLocal semantic memory — saves and recalls past conversations
robot_actions.pyMac actions — search, notes, open apps, system info

Install & keys

Use a Python 3.11 environment, then:

# from the folder with the three files
python3.11 -m venv venv
source venv/bin/activate
pip install openai elevenlabs sounddevice httpx fastembed numpy

# your keys (they reset each terminal session)
export OPENAI_API_KEY="..."
export ELEVENLABS_API_KEY="..."

Point it at your robot & voice

Near the top of bot_brain_realtime.py, set two things — the address from the Serial Monitor, and the ID of a voice you cloned in the ElevenLabs dashboard:

BOT_IP    = "192.168.1.XX"   # from Serial Monitor
VOICE_ID  = "your-cloned-voice-id"

Run it

python bot_brain_realtime.py

First run downloads a small memory model (once), then it's listening. Everything it does prints to the console with timestamps — you can watch it hear you, look, think, and reply:

[LISTEN] you started talking
[STT]    you said: 'what time is it?'
[MEMORY] recalled 2 item(s)
[CAMERA] frame captured (10930 bytes)
[BOT]    It's just past 9 in the evening.
Keep it in one folderAll three files, and everything you run, live in a single folder. Scattered copies with the same name in different folders is the single biggest time-sink in a project like this — you edit one and run another and chase a bug that isn't there.

07

Hard-won lessons

The things that cost hours. Skip the pain.

The robot talks over itself

A fully live voice on laptop speakers hears its own audio through the mic and cuts off mid-sentence. Fix: mute the mic while it speaks (built in), or use headphones. Physically separating the mic and speaker is the real cure.

Camera won't start

"frame buffer malloc failed" means PSRAM is off. Set OPI PSRAM in the board menu and re-flash. Cold-boot flicker is usually weak USB power — use a good cable.

Camera image is upside down

Depends how the sensor sits. One line in the firmware flips it (set_vflip / set_hmirror). Check the photo in a browser at /capture.

Ghost file copies

Editing one file while running another with the same name in a different folder. One folder, one copy of each file, always.

The face won't change

Tap a face on the control page — if the status text updates but the OLED doesn't, it's the display; if the text doesn't update, it's the network or a wrong IP (check the Serial baud rate matches).

Two microphones fight

On macOS, opening the mic twice gives the second one silence. If you add wake-word or extra audio, share one mic stream.
